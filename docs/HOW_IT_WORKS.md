# Как это работает

## BLE Advertising и сканирование

BLE-устройства периодически рассылают "advertising"-пакеты — короткие
широковещательные сообщения о своём присутствии (обычно раз в
несколько сотен миллисекунд - несколько секунд). Сканер (наша BW16)
слушает эти пакеты, не подключаясь к устройству.

Мы используем официальную библиотеку `AmebaBLE` (класс `BLEDevice`,
глобальный объект `BLE`):

```cpp
#include "BLEDevice.h"

BLE.init();
BLE.configScan()->setScanMode(GAP_SCAN_MODE_ACTIVE); // или GAP_SCAN_MODE_PASSIVE
BLE.configScan()->setScanInterval(100);
BLE.configScan()->setScanWindow(90);
BLE.configScan()->updateScanParams();
BLE.setScanCallback(scanFunction);
BLE.beginCentral(0);
BLE.configScan()->startScan();       // без аргумента = непрерывно
// BLE.configScan()->startScan(5000); // с аргументом = остановится через 5000 мс
```

Каждый раз, когда обнаруживается пакет, вызывается `scanFunction`, где мы
разбираем данные через `BLEAdvertData`:

```cpp
BLEAdvertData foundDevice;

void scanFunction(T_LE_CB_DATA *p_data) {
  foundDevice.parseScanInfo(p_data);
  String addr = foundDevice.getAddr().str();   // MAC-адрес
  int8_t rssi = foundDevice.getRSSI();          // сила сигнала
  if (foundDevice.hasName()) {
    String name = foundDevice.getName();
  }
}
```

**Active vs Passive сканирование:**
- `GAP_SCAN_MODE_ACTIVE` — после получения рекламного пакета сканер
  дополнительно запрашивает scan response (там иногда есть доп. данные,
  например полное имя устройства). Чуть больше нагружает эфир.
- `GAP_SCAN_MODE_PASSIVE` — только слушаем, ничего не запрашиваем.
  Более "тихий" режим, подходит для фонового мониторинга (используется в
  Anti-Tracker Alert).

## RSSI и расстояние

RSSI — это не расстояние в метрах, а логарифмическая мера мощности сигнала
на приёмнике. Грубая связь такая:

```
RSSI ≈ TxPower - 10 * n * log10(расстояние)
```

где `n` — коэффициент затухания среды (в воздухе без препятствий ~2,
в помещении со стенами может быть 3-4). Поскольку `TxPower` разный у
разных устройств и не всегда известен, а `n` меняется от комнаты к
комнате, точный расчёт метров ненадёжен. Поэтому Item Finder использует
RSSI напрямую как относительный индикатор "ближе/дальше", а не переводит
его в конкретные метры.

## Anti-Tracker: почему именно "длительность присутствия"

Реальные приложения защиты от слежки (например, Apple/Google's system для
AirTag, или сторонние вроде AirGuard) в основном комбинируют:
1. Длительность, в течение которой устройство продолжает быть рядом
2. Признаки того, что вы физически перемещались, а устройство "ехало" с вами
   (что требует истории геолокации — этого у нас нет на голой плате)

Наш скетч упрощённо использует только пункт 1: если анонимное BLE-устройство
непрерывно "видно" дольше `PERSISTENCE_THRESHOLD_MS` — это повод присмотреться.
Это даёт больше ложных срабатываний, чем полноценные системы с GPS, но зато
работает автономно на дешёвой плате без сети и телефона.
